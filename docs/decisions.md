# 决策记录：为什么这么定，以及哪些方案被否决了

> 只看「现在怎么做」读 `AGENTS.md`；这里写的是**为什么**，特别是那些看起来像 bug、
> 其实是权衡结果的地方。想推翻其中一条，先读完对应条目和它的否决理由。

---

## D-01 解析器不接收时区参数

**决定**：`cal-mcp/src/nlp.mjs` 全程使用进程本地时区的 `getHours` / `getFullYear` 语义，
不为它新增 `timeZone` 参数。时区只影响**写入与显示**（`config.timeZone`）。

**原因**：解析器是纯函数、零 import，150+ 条蓝本用例都跑在固定 `TZ` 下。给它穿一套时区参数
要重写整套日期语义，跨 DST 切换日极易算错，收益（非中国时区用户的口语理解）远小于风险。

**被否决的方案**：把 `parseEvent(text, now, tz)` 做成显式时区上下文；或用 Temporal API
（Node 18 不可用，且仍是零依赖原则的破坏者）。

## D-02 「每周三次」直接报错，不猜

**决定**：`每周三次 健身` → 报错并提示改写成「每周一三五」。

**原因**：日历的 RRULE 只认 BYDAY。猜一个具体分布等于替用户编造日程，而写错的日程用户不会发现。

**被否决的方案**：静默降级成每周一次（旧行为，属于真 bug）；或按「一三五」自动补全（等于编造）。

## D-03 队列落盘不做 fsync

**决定**：靠「写临时文件 + rename」保证不读到半个文件，不调用 `fsync`。

**原因**：量过。30 并发入队从 5.4 秒退化到超时。rename 的原子性足以覆盖「进程崩溃」这个真实场景，
剩下的是断电丢最后一条——可接受。

## D-04 越界输入一律报错，不夹到边界

**决定**：`25点`、`3点75分`、`2月30号` 抛错。

**原因**：产品原则是**报错优于猜测**。夹到边界会悄悄写出一个用户没打算建的日程。

## D-05 重定向凭据走白名单，不是「末两段域名相同」

**决定**：`isTrustedHop()` 里维护 Apple 自有 zone 的固定表，跨 zone 一律拒绝并提示服务器地址。

**原因**：公共后缀（`co.uk` / `com.cn` / `github.io`）下末两段相同不代表同一注册者。
比较域名后缀是安全反模式。

**代价**：Apple 新增 zone 时要改表。已用「把 Apple 自有 zone 当一整组」降低维护频率。

## D-06 删除必须 `confirm === true`

**决定**：业务层与 MCP 层各一道闸，字符串 `"false"` 必须不删。

**原因**：模型生成的参数是字符串。`if (args.confirm)` 会把 `"false"` 当成真。

## D-07 产品名 `dsh-cal` 与仓库名 `dsh-calendar` 不一致，不改

**决定**：维持现状。

**原因**：改名会牵连 Release URL、安装路径、bundle id、启动器路径。功能零影响，
风险与收益不匹配。

## D-08 钥匙串 ACL 过宽只写文档，不改代码

**决定**：在 README 里写清威胁模型与 ACL 现状。

**原因**：授信范围由用户决定，收紧 ACL 会让「换模型接力」时读不到凭据，运维代价大于收益。

## D-09 不做跨应用「只让空隙点击穿透」

**决定**：不实现。`NSWindow.ignoresMouseEvents` 是整窗开关，单窗口架构下做不到局部穿透。

**原因**：动态切开关需要全局鼠标监听，有点击竞态与拖动断流风险，且**无法自动验证**。
要做干净得把木板拆成独立无边框窗口（架构级重构）。在没有 GUI 验证手段之前不塞未经检验的 hack。

## D-10 拟物外观用 WKWebView 承载，不继续用 AppKit 逐笔重画

**决定**：`cal-app/web/skeuo.html` 由 WKWebView 承载，`App.swift` 只留一层外壳与 JS↔原生桥。

**原因**：上一轮 AppKit 手绘做了 build 8–18，两套渲染引擎始终对不上（HTML 视觉稿与真机差距过大）。
换成 WebView 后材质与视觉稿同源，改版成本从「重写 Swift 绘制」降到「改 CSS」。

**代价**：behind-window 模糊之类的系统级材质拿不到，需在 HTML 侧用降级方案近似。
