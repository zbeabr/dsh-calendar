# 复盘：这次「模型为什么没兜住」

2026-11-07 · **只复盘，不改代码**。项目所有者明确说：开源分发暂时做不到本地模型普及，
模型这一层目前只有他自己用，所以这一轮不调整 `llm.mjs`、提示词或触发条件。
本文把原因写清楚，留给以后真要动这块的时候有个起点。

---

## 1. 现场：模型其实**被调用了**，不是没触发

出问题的句子是「下下周三中午吃个半小时的张亮麻辣烫」。改代码之前，
`node cli.mjs parse "下下周三中午吃个半小时的张亮麻辣烫"` 的实测输出（节选）：

```json
{
  "title": "吃个的",
  "location": "张亮麻辣烫",
  "local": "11/18周三 12:00–12:30",
  "byModel": "ollama:qwen3:8b",
  "needsModel": true
}
```

规则层给的标题是 `吃个的张亮麻辣烫`（时间三项全对，坏在标题），
CLI 走完模型后变成 `title: "吃个的"` + `location: "张亮麻辣烫"` —— **更差了**，
而且这个更差的结果被写进了返回值。`byModel` 不是 null，说明模型确实出过力。

所以问题不是「没用模型」，而是「用了模型，却既没让它修标题，也没拦住它把事情改坏」。
下面每一条都对应一处真实代码，行号以 2026-11-07 的 `main` 为准。

## 2. 六条具体原因

**① 触发靠启发式，不靠置信度。** `cli.mjs:195` 的条件是
`needsRefine(text, parsed) || !parsed.location`；`src/llm.mjs:196` 的 `titleNeedsWork`
只查三件事：弱标题正则 `WEAK_TITLE`（`:183`）、标题里有没有时间词、长度有没有超过 16。
`吃个的张亮麻辣烫` 九个字、没有「帮我/在/一下」这类前缀、也没残留时间词，
于是被判成「规则已经处理干净」。**规则判错了自己，补丁就跟着失效**。

**② `lockTitle` 把模型的手绑住了。** `src/llm.mjs:275`：
`const lockTitle = Boolean(base) && !needsRefine(text, ruleResult);`
一旦标题被判干净，`refineWithModel` 就只让模型补地点，根本不调用 `verifyTitle`
（`:278` 附近 `let title = lockTitle ? undefined : verifyTitle(...)`）。
也就是说，模型这次连「重写标题」的资格都没有——它再强也只能通过 `location` 这个字段影响结果。

**③ 护栏是字符串匹配，不是语义。** `src/llm.mjs:263` 有一道专门防「把动词宾语当地点」的护栏：
`objectAsLocation` 要求 `VERB_OBJECT.test(base.slice(0, base.length - location.length))`，
即动词必须**紧挨**店名（`吃张亮麻辣烫` 能命中，`吃个的张亮麻辣烫` 切出来是 `吃个的`，
以「的」结尾，`VERB_OBJECT`（`:188`）判不出来）。这次它正好被那截「个的」残渣绕开了。
护栏的本意是对的，实现却脆得只需要一个虚词就能击穿。

**④ 验收只看「合法」，不比较「谁更好」。** `verifyTitle`（`src/llm.mjs:165`）三道闸是：
是不是原文子序列、有没有时间词、长度 2–40。`吃个的` 三条全过，于是被采纳。
`cli.mjs:205` 直接 `refined?.title ?? parsed.title`——**模型优先**，没有「模型结果必须不差于规则结果」
这一步。一个更差的答案只要合法，就能盖掉规则答案。

**⑤ 模型被限制在极窄的职责里，也没有示例。** 它只输出 `title` / `location` 两个字段，
时间仍由规则算；`SYSTEM_PROMPT` / `userPrompt` 里没有 few-shot 告诉它
「『吃 X』里的店名回答的是吃什么，不是在哪」。本地 `qwen3:8b` 这种尺寸的模型
对中文口语句式的判断本来就不稳，没有示例时更容易顺着「店名 = 地点」的直觉走。
（这一条是读提示词后的推断，**没有模型内部日志可证**。）

**⑥ 失败是静默的。** `refineWithModel` 任何异常都返回 `undefined`，调用方继续用规则结果；
而「模型给了更差的答案」根本不算异常，连日志都没有。这类问题只能靠人拿一句话试出来——
这次就是这么发现的，不是靠任何自动检查。

## 3. 更深一层：让被审查者决定要不要被审查

这个产品的主路径是规则解析器（毫秒级、离线、可测试），模型是补丁，默认 `llm.enabled=false`。
补丁要不要出场，由 `needsRefine` 这个**同样属于规则层**的启发式决定。
于是规则一旦把自己判成「干净」，就同时关掉了唯一能纠正它的通道。
这是结构性的，不是某条正则写错。换个句子、换一种残渣，同样的失效还会再来。

这也解释了为什么这次修法选在规则层（`nlp.mjs` 的 `DANGLING_DE` 清洗）而不是调模型：
把标题洗干净之后，动词重新紧挨宾语，既有的 `objectAsLocation` 护栏自然命中，
模型那条坏结果被整条丢弃。**修规则层的因，比修兜底层的果便宜得多。**

## 4. 为什么这一轮不改模型侧

- **分发现实**：默认路径要能在没有 ollama、没有几 GB 权重、纯离线的机器上跑。
  「零依赖、不出这台电脑」是 README 里写明的承诺，把主路径改成模型优先会直接违约。
- **测试前提**：152→165 条解析用例都建立在「纯函数、固定 TZ、无网络」上；
  让模型进入主路径，这套可复现的基线就没了。
- **所有者的决定**：这部分目前只有他自己用，先不动；开源侧先靠规则层自己变强。
- 因此本轮 `llm.mjs`、`SYSTEM_PROMPT`、`cli.mjs` / `tools.mjs` 的触发条件**一行未改**。

本轮做的替代是把「规则层必须自己兜住」固化成可执行的契约：
`cal-mcp/parse-corpus.mjs` + `parse-corpus.snapshot.txt`（302 条生活口语，纳入 `npm test`），
加上 `parse-cases.mjs` 里 11 条精确断言。它们不依赖任何模型，CI 的 UTC runner 也能跑。
以后任何版本只要把标题、时间、地点、报错文案改偏一点，蓝本就会指名道姓报出来。

## 5. 将来真要做，方向清单（**本轮不实施**）

1. 触发条件从「脏标题启发式」换成**规则置信度**：比如 spans 覆盖率、标题可疑分数，
   或者规则与模型并行出结果后再比较，而不是让规则单方面决定要不要问模型。
2. 增加一道**质量闸**：模型结果必须不差于规则结果才采纳（标题是否仍含残渣、
   是否把动词宾语切走、子序列长度差、是否引入新地点）。现在是「合法即采纳」。
3. 护栏语义化：`objectAsLocation` 识别「动词 + 量词 + 宾语」，别要求动词紧邻；
   或者直接让模型同时给出 `location` 的角色（在哪 / 吃什么）。
4. 提示词补 few-shot，把「吃什么 ≠ 在哪」「半小时的是时长不是定语」写成例子。
5. 模型调用结果落一份脱敏日志（触发原因、规则答案、模型答案、最终采纳了谁），
   让「模型把事情改坏」变成能被统计的事件，而不是靠用户偶然发现。
6. 硬约束不变：**没有模型时，规则结果必须完整可用**，且现有 302 条蓝本要保持全绿。

## 6. 复现方式

```bash
cd cal-mcp
node cli.mjs parse "下下周三中午吃个半小时的张亮麻辣烫"      # 现在应给出「吃张亮麻辣烫」
node cli.mjs parse "下下周三中午吃个半小时的张亮麻辣烫" --fast # 纯规则，不调模型
node parse-corpus.mjs --show | grep 张亮麻辣烫                 # 蓝本里的同句
```
